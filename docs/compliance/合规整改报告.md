## 一、产品事实（决定哪些义务适用）

整改前先把事实说清楚，避免"为了合规而合规"地堆一堆不适用条款。

| 事实 | 说明 |
| --- | --- |
| 无账号体系 | 不注册、不登录、不采集手机号/身份证 |
| 无云端服务器 | 开发者没有任何后端，收不到用户的业务数据 |
| 数据落点 | 手机应用私有目录（`localStorage` + 应用私有文件），电脑端为本地 SQLite |
| 唯一的网络行为 | 用户主动开启"数据共享到电脑端"后，与**同一局域网内自己的电脑**经 HTTP 通信 |
| 第三方 SDK | 无。OCR 为本地 ONNX 推理（PP-OCR），随安装包内置 |
| 分发方式 | 内部分发（不上架应用商店） |
| 目标用户 | 经营者（个人/小商户）盘货用，不面向儿童 |

因此以下条款**不适用**，报告中不再逐条列出：真实身份信息认证（《App 规定》第 6 条）、
信息内容审核（第 8 条）、新闻许可（第 7 条）、账号注销（无账号）、算法推荐与自动化决策
（PIPL 第 24 条）、个人信息出境（PIPL 第三章）、重要数据风险评估（《数据安全法》第 30 条）、
关键信息基础设施义务（《网络安全法》第三章第二节）。

## 四、残余风险与后续建议

按影响从高到低：

1. **本地数据库明文**。手机端数据在 `localStorage`，电脑端为明文 SQLite。已用应用私有目录 + 关闭系统备份
   + 可选启动验证缓解，但 root / 取证工具仍可读取。若要彻底解决，需引入 SQLCipher 或对字段做应用层加密
   —— 代价是改造量较大且影响导出格式，本轮未做。
2. **局域网明文 HTTP**。局域网共享不带 TLS（自签证书对普通用户落地成本高）。已通过"仅私有网段"
   + 令牌绑 IP + 12 小时过期 + 失败锁定 + 连接码不落盘把风险压到"同网段可嗅探但拿不到有效凭据"。
   建议在共享界面加一句"请只在可信 Wi-Fi 下开启共享"的提示（待办）。
3. ~~**隐私政策联系邮箱待填**~~（2026-11-28 已完成：已填入 1608297736@qq.com，
   `android/assets/legal/privacy.txt`、`docs/compliance/隐私政策.md` 同步更新）。
4. **合规审计未执行**。PIPL 第 54 条的定期审计需人工执行，制度里已定义检查表，尚未跑第一轮。
5. **未做第三方渗透/源码审计**。出网白名单只覆盖 WebView 层；若后续引入原生网络代码，需在 OkHttp/
   HttpURLConnection 层同样加白名单。

## 六、变更纪律

1. 任何涉及权限增删、数据字段增删、出网行为的改动，必须同步更新《个人信息收集使用清单》与隐私政策，
   并递增 `Legal.VERSION`，否则老用户不会重新看到同意页 —— 这是最容易漏的一条。
2. 日志留存天数不得低于 180 天（法规下限 6 个月）。修改 `wm/audit.py KEEP_DAYS` 需说明理由。
3. 新增第三方 SDK 必须先在《个人信息收集使用清单》登记 SDK 名称、收集字段、用途、隐私政策链接，
   并在首启同意页披露；未登记不得合入。
