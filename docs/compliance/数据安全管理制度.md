# 数据安全管理制度

制定依据：《中华人民共和国网络安全法》第 23 条、《中华人民共和国数据安全法》第 27 条、
《中华人民共和国个人信息保护法》第 51 条、《移动互联网应用程序信息服务管理规定》第 11 条。

适用范围：仓管家手机版 Android App、仓管家电脑端及其配套的局域网共享服务。

版本：v1.0　生效：2026-11-02　责任人：仓管家 个人开发者

---

## 第一章 组织与职责

1.1 本产品为个人开发、内部分发的小型工具，不设独立安全部门，由**开发者本人**担任数据安全负责人，
对数据安全与个人信息保护负总责。

1.2 负责人职责：

- 维护本制度与《个人信息收集使用清单》，确保与实际代码一致；
- 版本发布前执行《发布前安全检查表》（第五章）；
- 受理用户的权利请求与投诉，15 个工作日内答复；
- 发生安全事件时启动应急响应，按规定上报；
- 每年至少组织一次合规自查（PIPL 第 54 条），并留存记录。

1.3 若后续引入协作者或外包，须签署保密协议，并在本制度中登记其可访问的数据范围。

## 第二章 数据分类分级

| 级别 | 定义 | 本产品中的对应数据 | 保护要求 |
| --- | --- | --- | --- |
| L3 敏感个人信息 | PIPL 第 28 条列举类型 | 无（商品照片可能含人脸，按 L2 上限管理） | — |
| L2 个人信息 | 可识别到自然人的信息 | 买家称呼、收货地址、商品照片、局域网 IP、崩溃日志中的设备信息 | 最小化采集、限定用途、访问受控、导出需用户主动操作 |
| L1 经营数据 | 不直接识别个人，但泄露损害经营者利益 | 型号、进价、售价、库存量、货位 | 沙箱隔离、关闭云备份、可选设备锁 |
| L0 公开/无风险 | 与个人和经营无关 | 程序代码、界面文案 | 常规管理 |

判定规则：字段同时具备"标识符 + 关联关系"（如"张先生 + 某小区"）时按 L2 处理。

## 第三章 数据生命周期管理

### 3.1 采集

- 只采集实现功能所必需的字段；买家称呼、照片、备注均为**可留空**项；
- 不采集设备标识符、位置、通讯录、应用列表、剪贴板；
- 相机权限"用时申请 + 用途说明"，相册使用系统选择器（不申请存储权限）；
- 首启必须主动勾选同意，未勾选不得进入。

### 3.2 存储

- 手机端：应用私有目录（`/data/data/com.cangguanjia.app/`），依赖 Android 沙箱隔离；
- 电脑端：本地 SQLite，与程序同目录的 `data/`；
- `android:allowBackup="false"`，禁止进入系统备份与云备份；
- 凭证类数据（连接码）**不落盘**；会话令牌仅在内存与本机存储中短期存在。

### 3.3 传输

- 仅在用户主动开启共享时，与同一局域网内的自有电脑通信；
- `NetGuard` 出网白名单：只允许 10/8、172.16/12、192.168/16、127/8、169.254/16、
  localhost 与内网单标签主机名；公网地址在 WebView 层直接拦截；
- 会话令牌与来源 IP 绑定，12 小时滑动过期，同一 IP 失败 5 次锁定 10 分钟；
- 明文 HTTP 仅在私有网段内使用（自签证书对普通用户不可行），风险与缓解见 PIA 第三章 R3。

### 3.4 使用

- 数据只用于库存管理、对账、核对实物与本地识别；
- 不做自动化决策、用户画像、定向推送；
- 拍照识别为本地推理，图像不落盘、不出设备。

### 3.5 删除

- 用户可逐条删除、批量清空、撤回同意（清除全部本机数据）；
- 访问日志 180 天自动清理；
- 崩溃日志在下次启动展示后立即删除；
- 卸载应用后私有目录数据随之删除。

## 第四章 访问控制与技术措施

| 措施 | 说明 | 落地 |
| --- | --- | --- |
| 设备级 | 可选"启动验证"，走系统锁屏（图案/密码/指纹），不自建密码以免用户遗忘后丢数据 | `MainActivity.awaitUnlock()` |
| 应用级 | 应用沙箱 + 私有目录；Provider 全部 `exported=false` + 临时 URI 授权 | `AndroidManifest.xml` |
| 网络级 | 出网白名单、禁混合内容、禁 `file://` 互读、关表单保存与定位 | `NetGuard.java` |
| 凭证级 | 连接码不持久化；令牌短期有效、绑 IP、失败限速 | `wm/mobile.py` |
| 审计级 | 访问日志记录时间/IP/方法/接口/状态码，180 天 | `wm/audit.py` |
| 备份级 | 关闭系统云备份；用户主动导出的 JSON 由用户自行保管 | 清单 + 应用内导出 |

**明确不做**：不采集 IMEI/OAID/Android ID 等不可重置标识符（既无必要，也避免触发
《移动互联网应用程序信息服务管理规定》对设备标识滥用的关注）。

## 第五章 发布前安全检查表

每次发版必须逐项确认，任一项不通过不得发布：

- [ ] 权限清单未增加；若有增加，已在同意页与隐私政策披露并说明必要性
- [ ] 未引入第三方 SDK；若有，已登记到《个人信息收集使用清单》并披露
- [ ] 个人信息字段未增加；若有，已更新清单与隐私政策，且 `Legal.VERSION` 已递增
- [ ] 首启同意页正常：不勾选不能进入、不同意可直接退出
- [ ] 撤回同意可清空数据并退出
- [ ] 导出功能可用，且导出内容**不含**会话令牌与连接码
- [ ] 出网白名单生效：输入公网地址被拒绝
- [ ] 访问日志仍在写，`KEEP_DAYS` 未被调低
- [ ] `tests/test_logic.py` 全绿（含合规断言）
- [ ] 部署包与源码一致（构建产物 md5 已记录）

## 第六章 安全事件应急预案

依据：《网络安全法》第 27 条、《数据安全法》第 29 条、《个人信息保护法》第 57 条。

### 6.1 事件分级

| 级别 | 判定标准 | 响应时限 |
| --- | --- | --- |
| 一般 | 单用户体验问题、崩溃、数据录入异常，无个人信息外泄 | 3 个工作日修复 |
| 较大 | 可复现的数据丢失或越权访问（如同一 Wi-Fi 下未授权设备读到库存） | 24 小时内出补丁方案 |
| 重大 | 个人信息泄露、篡改、丢失，或产品缺陷导致批量外泄 | **立即**处置，72 小时内上报 |

### 6.2 处置流程

1. **发现**：用户反馈（邮件/截图）、自查、崩溃日志异常增多、访问日志出现异常 IP 或高频 401/403。
2. **止损**：立即停止分发受影响版本；指导用户关闭"数据共享"；必要时让用户撤回同意并清除数据。
3. **取证**：保全 `data/logs/access-*.log`、崩溃日志、版本号与时间线，不做破坏性操作。
4. **修复**：定位缺陷 → 出补丁 → 回归（含合规断言）→ 灰度给反馈用户 → 全量。
5. **通知**（重大事件）：
   - 通知受影响用户：事件内容、可能影响、已采取措施、用户可采取的措施、联系方式；
   - 上报主管部门：按属地网信/公安要求提交书面报告，内容包括时间、原因、影响范围、
     已采取措施、后续计划。
6. **复盘**：15 日内形成复盘记录，更新本制度与检查表，纳入下一版回归断言。

### 6.3 用户通知模板（要点）

> 我们于〔日期〕发现〔问题描述〕，可能影响〔数据范围〕。我们已于〔时间〕完成〔处置措施〕。
> 建议您〔用户可采取的措施，如修改 Wi-Fi 密码、关闭共享、导出备份后清除数据〕。
> 如有疑问请联系〔邮箱〕。

### 6.4 常见场景处置速查

| 场景 | 首要动作 |
| --- | --- |
| 手机丢失 | 用户侧：远程锁定/擦除设备；产品侧：无法远程清除（无账号体系，属设计取舍），故建议开启启动验证 |
| 局域网被陌生设备连接 | 主机"手机全部下线"→ 换连接码 → 加入黑名单 → 查看访问日志确认访问范围 |
| 导出文件误发他人 | 提示用户尽快删除该文件；导出的 JSON 含明文业务数据，无法远程失效 |
| 崩溃日志含敏感信息 | 当前仅记录堆栈与版本号，不含业务字段；若未来加入上下文，须先脱敏 |

## 第七章 培训与审计

7.1 培训：每次引入新功能（尤其是联网、权限、第三方库）前，开发者须复核本制度与清单，
并在提交信息中注明合规影响。

7.2 审计：每年至少一次，检查项包括——
权限集是否仍为最小集；隐私政策是否与实际处理一致；是否新增 SDK；
日志留存是否满足 180 天；权利请求是否在 15 个工作日内答复；是否发生未上报的安全事件。

审计记录与《个人信息保护影响评估》一并保存**不少于 3 年**。

## 第八章 附则

8.1 本制度与《隐私政策》冲突时，以对用户更有利的表述为准，并立即修订另一份。

8.2 本制度自 2026-11-02 起施行，修订须记录版本与变更点。
