## 一、处理活动描述

### 1.1 处理者与角色

- 处理者：仓管家 个人开发者（联系方式见隐私政策第一节）。
- 角色特点：**本产品不构成"平台型"处理者**。业务数据默认只存在于用户设备上，开发者不接触；
  唯一由开发者设计的传输路径是"用户手机 → 用户自己的电脑"，两端都属用户控制范围。
- 因此本评估的重点不是"开发者如何使用数据"，而是"产品设计是否把用户置于可控、可预期、
  可撤回的位置"。

### 1.2 处理目的与必要性

| 目的 | 支撑功能 | 必要性说明 | 替代方案 |
| --- | --- | --- | --- |
| 库存台账 | 录入/导入/查询 | 产品核心，无此即无产品 | 无（可退回纸质台账） |
| 销售对账 | 出售记录、买家称呼、金额 | 对账与复盘需要 | 买家称呼可留空 |
| 实物核对 | 商品照片 | 型号相似时靠照片区分 | 可不用照片，改用手写备注 |
| 录入效率 | 拍照识别型号/二维码 | 减少手工输入错误 | 手动输入 |
| 手机与电脑互通 | 局域网共享 | 用户既有电脑端使用习惯 | 可只用手机，不开启共享 |
| 故障定位 | 崩溃日志 | 无日志则移动端问题无法定位 | 用户主动描述现象 |
| 安全审计 | 访问日志 | 法定义务（《网络安全法》第 23 条） | 无（法定义务） |

### 1.3 信息类型与规模

- 类型：经营者自有的商品与交易数据；买家称呼（可识别到自然人）；商品照片；IP 地址。
- 规模：单机工具，单个用户的数据量为数百至数万条记录；开发者侧收集量为 **0**。
- 敏感个人信息：**不处理**《个人信息保护法》第 28 条列举的七类敏感信息（生物识别、宗教信仰、
  特定身份、医疗健康、金融账户、行踪轨迹、不满十四周岁未成年人信息）。商品照片在极端情况下
  可能拍摄到人脸，属"可能涉及"，已在第八章列为残余风险。

### 1.4 处理方式

采集（用户手动录入/拍摄）→ 存储（设备本地）→ 使用（本机查询统计）→ 传输（可选，局域网）
→ 删除（用户主导）。**无自动化决策、无用户画像、无定向推送、无跨境传输、无委托处理。**

## 二、对个人权益的影响分析

| 权益维度 | 潜在影响 | 可能性 | 严重程度 | 综合评价 |
| --- | --- | --- | --- | --- |
| 知情权 | 整改前隐私政策要素不全，用户不清楚处理者是谁、数据存多久 | 高（已发生） | 中 | 整改后消除 |
| 选择权 | 整改前协议与政策混装、无法单独同意 | 高（已发生） | 中 | 整改后消除 |
| 财产权益 | 库存与售价属经营信息，泄露可能被同行/买家利用 | 中 | 中 | 通过隔离与访问控制缓解 |
| 人身权益 | 买家称呼 + 收货地址组合可定位到具体个人 | 低 | 中 | 字段可留空；不强制采集 |
| 人格尊严 | 商品照片若拍到人脸，可能构成肖像信息处理 | 低 | 低 | 识别图像不存储；照片由用户自主选择 |
| 救济权 | 整改前无导出、无撤回，用户被"锁死" | 高（已发生） | 中 | 整改后消除 |

**不存在的影响**：不会因使用本产品导致用户被电话骚扰、被精准营销、被差别定价 ——
因为不存在任何对外提供与自动化决策。

## 三、风险识别（按场景）

| # | 风险场景 | 成因 | 现有控制 | 残余风险等级 |
| --- | --- | --- | --- | --- |
| R1 | 手机丢失/被他人借用，库存被查看 | 应用无锁屏 | 可选启动验证（系统锁屏）；应用私有目录 | 低 |
| R2 | 手机被 root / 取证工具提取，明文数据外泄 | `localStorage` 与 SQLite 明文 | 关闭系统备份；沙箱隔离 | **中** |
| R3 | 同网段嗅探局域网 HTTP 流量 | 无 TLS；连接码与数据明文 | 令牌绑 IP、12h 过期、失败锁定；连接码不落盘；仅私有网段 | 中 |
| R4 | 页面被篡改后把数据发往公网 | WebView 可跨源请求 | `NetGuard` 出网白名单 + 页面侧地址校验 + 禁混合内容 | 低 |
| R5 | 日志本身成为第二份个人信息库 | 日志若记录业务内容 | 只记元数据（时间/IP/接口/状态码），不记型号买家金额；180 天清理 | 低 |
| R6 | 崩溃日志被他人读取 | 存于私有目录，启动即展示 | 展示后立即删除 | 低 |

| R8 | 权限过度申请导致"偷看相册"观感 | 整改前申请 `READ_MEDIA_IMAGES` | 已移除，改系统选择器 | 已消除 |
| R9 | 政策变更后用户"被默认同意" | 整改前布尔标记 | 版本号比对，升版重新征得同意 | 已消除 |
| R10 | 用户无法带走自己的数据 | 无导出 | JSON 导出 + 系统分享 | 已消除 |

## 四、与合法性基础的匹配性

| 处理活动 | 合法性基础 | 是否满足 |
| --- | --- | --- |
| 库存/出售/照片/配置 | PIPL 13(1) 取得个人同意 | 首启主动勾选，可撤回 |
| 相机、相册访问 | PIPL 13(1) + 第 29 条（敏感信息单独同意） | 使用时单独弹窗说明用途，可拒绝，拒绝不影响基本功能 |
| 局域网传输 | PIPL 13(1)；接收方为用户本人设备 | 用户主动开启，随时断开 |
| 访问日志留存 | PIPL 13(3) 履行法定义务（《网络安全法》23 条） | 依法留存，最小化字段，180 天后删除 |

不存在以"订立合同所必需""为履行法定职责"等为由扩张处理范围的情形。

## 五、告知与同意的有效性评估

| 检查点 | 要求 | 现状 |
| --- | --- | --- |
| 告知时点 | 处理前 | 首启同意页在创建 WebView 之前展示 |
| 告知内容 | PIPL 17 五项要素齐全 | 隐私政策十节，逐项覆盖 |
| 同意方式 | 自愿、明确、主动 | 复选框默认不勾选，未勾选点"同意"不放行 |
| 单独同意 | 敏感信息、对外提供需单独取得 | 相机权限单独弹窗；共享功能单独开启 |
| 拒绝的后果 | 不得以拒绝非必要信息为由拒绝基本功能 | 拒绝相机仍可用全部库存功能 |
| 撤回 | 便捷、与同意同等容易 | 设置页两级点击即可撤回 |
| 变更 | 目的方式种类变更需重新告知同意 | 版本号机制强制重新展示 |

## 六、个人权利保障评估

导出（复制/可携带）与撤回同意是本次整改投入最大的两块，评估结论：

- **导出**：一次导出全部数据（记录 + 照片 + 配置），格式为开放 JSON，经系统分享面板交给用户，
  不依赖开发者服务器，也不申请存储权限。满足"可携带"的实质要求。
- **撤回**：撤回后清除本机全部数据（含 WebView 存储、Cookie、照片、崩溃日志、偏好），并退出应用；
  同时保留"已同步到电脑的数据需在电脑端自行删除"的明确提示，避免用户误以为已彻底删除。
- **删除**：支持单条、批量、整体三个粒度，均在应用内即时生效，无需申请审批。

## 九、评估结论

1. 本产品处理个人信息的**目的明确、范围最小、期限可控**，不存在与提供服务无关的收集。
2. 整改后已具备完整的告知—同意—权利保障闭环，符合《个人信息保护法》第 13、14、15、17、19、
   44—47、51、55—57 条的要求。
3. 在落实第七章控制措施的前提下，**剩余风险处于可接受水平**，可继续处理并对外分发。
4. 出现下列情形须**重新评估**：新增第三方 SDK；新增联网功能或云端存储；新增个人信息字段；
   新增对外提供场景；用户量级发生数量级变化。
