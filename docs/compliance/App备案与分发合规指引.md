# App 备案与分发合规指引

适用产品：仓管家手机版 v1.32.0（`com.cangguanjia.app`）  
分发方式：内部分发（不上架应用商店）  
编制日期：2026-11-02

---

## 一、先判断：你到底需不需要备案

很多工具类 App 的开发者在这里走了弯路。备案义务分三层，判断依据各不相同：

| 层级 | 依据 | 触发条件 | 本产品 |
| --- | --- | --- | --- |
| ICP 备案（网站/域名） | 《互联网信息服务管理办法》 | 有域名、有对公网提供服务的服务器 | **不涉及**：无域名、无服务器 |
| **App 备案** | 工信部《关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105 号） | 在境内**从事互联网信息服务**的 App；通过应用商店分发的须先备案 | **当前不触发**；上架商店时触发 |
| 应用商店上架审核 | 各分发平台规则 + 《移动互联网应用程序信息服务管理规定》第 19、20 条 | 上架即触发 | 当前不涉及 |

### 本产品的判断

1. App 仅与**同一局域网内用户自己的电脑**通信，不向公网提供任何信息服务，不设服务器与域名，
   开发者侧不接收任何数据 —— 不构成"互联网信息服务"，因此**不触发 App 备案**。
2. 例外：一旦上架任何应用商店，**平台会强制要求提供 App 备案号**（这是分发平台的审核义务，
   不是你可以选择的事项）。此时必须先备案再提交上架。
3. 判断口径存在地区差异。若计划规模化分发或商用，建议向属地通信管理局书面咨询一次，
   并把答复留档 —— 这比事后解释成本低得多。

## 二、如果要备案：材料与流程

### 2.1 办理入口

通过**网络接入服务提供者**（云服务商、IDC、CDN）或其备案系统提交，最终进入工信部
"ICP/IP 地址/域名信息备案管理系统"。本产品无接入服务商时，可咨询属地通信管理局指定的受理渠道；
部分分发平台也提供代备案入口。

### 2.2 个人主体材料清单

| 材料 | 说明 |
| --- | --- |
| 身份证正反面 | 需与手机号实名一致 |
| 手机号、邮箱 | 用于核验与接收通知 |
| App 名称 | 与安装后显示名称一致：**仓管家** |
| App 包名 | `com.cangguanjia.app` |
| 平台类型 | Android |
| 签名证书 MD5 | 用 `apksigner verify --print-certs` 或 `keytool -list -v` 取 |
| 公钥 | 同上，`apksigner` 输出的公钥 |
| SDK 服务商情况 | 本产品未集成第三方 SDK，填"无" |
| 域名 / IP | 无（仅局域网直连），按实际情况留空或填"无" |
| 服务内容描述 | "本地库存管理工具，不提供互联网信息服务" |

> 签名 MD5 每次换签名证书都会变，务必用**正式发布证书**（`android/cgm-release.keystore`）的指纹备案，
> 不要用调试证书。

### 2.3 流程与时间

提交 → 接入商初审（1—3 个工作日）→ 管局审核（一般 1—20 个工作日）→ 下发备案号。
备案号需在 App 内"设置 → 关于"处展示（上架时平台会核查）。

> 当前版本**故意没有**备案号展示位：没有备案号却挂一个空位或假号，比不展示更糟。
> 确定备案后再加，位置建议放"设置 → 隐私与数据"卡片底部。

## 三、上架前合规检查表（若将来上架）

### 3.1 必备材料

- [ ] 隐私政策**可公网访问的链接**（当前隐私政策只在 APK 内，上架前必须托管一份网页版）
- [ ] 用户协议链接
- [ ] App 备案号
- [ ] 软件著作权或授权证明（部分平台要求）
- [ ] 签名证书与包名一致性说明
- [ ] 应用截图（含首启同意页、设置页隐私入口）

### 3.2 应用商店"隐私标签 / 数据安全表单"填写建议

按《个人信息收集使用清单》逐项填写，本产品的填法相对简单：

| 表单问题 | 填写 |
| --- | --- |
| 是否收集用户数据 | 是（仅在设备本地处理） |
| 收集的数据类型 | 照片/视频（用户主动选择）、其他用户内容（库存与交易记录）、设备或其他 ID（**否**） |
| 数据是否共享给第三方 | 否 |
| 数据是否传输加密 | 局域网内为明文 HTTP（仅私有网段），需如实说明 |
| 是否支持用户删除数据 | 是（应用内清空 / 撤回同意） |
| 是否含广告 | 否 |
| 是否面向儿童 | 否 |

> 表单里"是否传输加密"如实填"否"不会导致被拒，填"是"而被抽检发现才是问题。

### 3.3 审核高频驳回点（本产品已提前处理）

| 驳回原因 | 本产品状态 |
| --- | --- |
| 首启未提示隐私政策 / 默认勾选同意 | 已改为复选框默认不勾选 ✅ |
| 未同意前就申请权限或初始化 SDK | 同意在创建 WebView 之前，权限在点击时申请 ✅ |
| 隐私政策缺处理者名称、联系方式、保存期限 | 已补齐 ✅ |
| 未说明权限用途、拒绝后不能用 | 已逐项说明并保留替代路径 ✅ |
| 索取与功能无关的权限 | 权限已减到 2 个 ✅ |
| 无账号体系却提供"注销"入口或反之 | 明确说明"无账号，卸载即终止" ✅ |
| 隐私政策与实际收集不一致 | 清单与代码对齐，回归断言约束 ✅ |

## 四、内部分发的注意事项

不走应用商店，不代表没有义务。以下三条最容易忽略：

1. **同意机制不能省**。首启同意、权限用途说明、撤回同意，都是法定义务，与是否上架无关。
2. **分发渠道要可控**。内部分发建议只发给明确的使用者，不公开下载链接；渠道不可控时，
   "内部分发"的主张很难成立。
3. **版本可追溯**。保留每个版本的 APK 与源码提交记录（`build_version.txt` 已记录），
   一旦被问"某版本收集了什么"，能立刻举证。

## 五、常见问答

**Q：个人开发者能备案吗？**
能，个人主体可备案，但部分省份对"个人备案 App"有额外核验要求，且个人备案不得用于经营性服务。

**Q：没有域名和服务器，能备案吗？**
App 备案表单项中域名/IP 可填"无"，是否受理取决于属地管局口径，建议先咨询。

**Q：不上架、只发微信/网盘，需要备案吗？**
不属于"通过分发平台提供"，但若 App 本身提供互联网信息服务仍需备案。本产品不提供，故不触发。

**Q：换了签名证书要重新备案吗？**
需要更新备案信息（MD5 与公钥变了）。这也是升级必须用同一把钥匙的原因之一。

**Q：备案号要展示在哪？**
通常要求"App 内可查"，放在设置页"关于/隐私与数据"处即可，避免放在首屏影响体验。
